# Поставки и тестовые данные

Все операции используют существующие CommandBusService, RabbitRPC и executeRpc. Exchanges, очереди, маски и формат RPC-ответа сохранены. Добавлены только команды редактирования поставки и сброса данных внутри существующих сервисов.

- `POST /supplies` принимает необязательный `status`: `RECEIVED`, `IN_TRANSIT`, `CANCELLED`. Без статуса сохраняется прежнее поведение: поставка принята и пополняет склад. Ожидаемые и отменённые поставки сохраняют позиции, но не создают складские партии.
- `PUT /supplies/:id` принимает ту же форму. Перевод из `IN_TRANSIT` в `RECEIVED` создаёт партии один раз. Повторное сохранение не дублирует остатки. Состав и статус принятой поставки нельзя менять, если партии уже использованы или зарезервированы; реквизиты можно редактировать. Конкурирующие изменения возвращают 409.
- `POST /inventory/:batchId/write-off` списывает весь доступный остаток партии и сохраняет `WRITE_OFF` в движениях. Зарезервированная партия возвращает 409. Повторное списание нулевого остатка не создаёт повторное движение. `PUT /inventory` сохраняет свой прежний контракт.
- `POST /test/reset` с `{ "confirmation": "RESET" }` последовательно очищает заказы, склад с поставками, каталог с рецептами. Пользователи, заведение, единицы измерения и последовательности ID не сбрасываются. Каждая операция сервиса транзакционная; при ошибке ответ сообщает завершённые этапы.

В production сброс отключён. Для отдельного тестового окружения он разрешается через `ENABLE_TEST_TOOLS=true` в gateway, inventory, catalog и order. Кнопка фронтенда дополнительно запрашивает подтверждение.

Наполнение на `/test` использует обычные API: `/product/units`, `/product/few`, `/supplies`, `/dishes/batch`. Рецепты и позиции поставки ссылаются на реально возвращённые ID; создаются 6 продуктов, 3 блюда и принятая поставка. Повторный запуск добавляет новый набор с уникальными именами. При частичном сбое уже созданные записи сохраняются.

«Оформить внешнюю поставку» — демо-импорт до трёх существующих продуктов со статусом `IN_TRANSIT`. Данные внешнего поставщика имитируются, сторонний сервис не вызывается. Приёмка выполняется через обычное редактирование поставки.

Изменения схемы БД и миграции для этих операций не требуются.
